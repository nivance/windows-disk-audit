# 对话内报告模板

在对话中直接输出，**默认不生成文件**。除非用户明确说"生成 HTML / 存成文件"。

---

## 标准结构

### 一、C 盘现状

首行给一句结论，例如：

> **C: 165 GB 总 / 已用 143 GB / 剩余 23 GB（87%）**

然后一张顶层目录表：

| 顶层目录 | 占用 | 说明 |
|---|---|---|
| `C:\Users` | **104 GB** | 主要消耗在这里 |
| `C:\Windows` | 30.9 GB | WinSxS 12.3 GB + System32 11.7 GB，系统本体不可动 |
| … | | |

用户目录量级大时，追加一张二级表（`AppData\Local` / `AppData\Roaming` / 各点目录）。

**口径一句**（`reconcile.code = inode-measured` 时写，否则跳过）：卷已用空间、目录项合计、去重合计是三个不同的数，报告里只用卷已用做"C 盘用了多少"，另外两个只在解释偏差时出现：

> 文件按目录项合计 164,981 MB，按文件去重 142,942 MB，卷已用 151,626 MB。前者高出的是 29.4 万个硬链接目录项（WinSxS 与 System32 共享），后者比去重值高的是 $MFT、目录索引、簇对齐等不落在文件数据流里的结构开销。

反例（不许写）：把 `totalMB` 当"C 盘占用"直接跟卷已用比，然后说"差额 8.4 GB 是硬链接" —— 差额里混了两种完全不同的东西。

### 二、为什么"掉得特别快"

这是本 skill 相对普通空间分析工具的核心价值。数据来自 `growth` 数组。

| 增长源 | 当前体积 | 增长特征 |
|---|---|---|
| Chrome Service Worker 缓存 | 13.3 GB | 按月累积：8月 1.9G → 9月 2.5G → 10月 3.7G，从不回收 |

- 首次运行（`previousAt` 为 `null`）时，明确说明"本次无历史可比，先建立基线"，不要编造增长率。
- 若 `growth` 为空但存在 `recentBig`，改用"最近 N 天内新增的大文件"作为增长证据，并注明这是按文件修改时间反推的。

### 三、可删清单

按 `risk` 分档，每档一张表。**必须逐项给出释放量**，用 `effectiveMB` 而不是 `mb`。

**✅ 可直接清理（约 XX GB）**

| 目标 | 释放 | 操作 |
|---|---|---|
| Chrome `Service Worker`（先完全退出 Chrome） | 13.3 GB | 删除该目录 |
| `AppData\Local\npm-cache` | 8.5 GB | `npm cache clean --force` |

**⚠️ 需你确认（约 XX GB）**

| 目标 | 释放 | 顾虑 |
|---|---|---|
| `.codex\sessions` | 2.3 GB | AI 对话历史，删了不可恢复 |
| … | | 用 finding 的 `cleanHint` / `why` 填这一列 |

两条收尾说明，`overlapMB > 0` 时必须写：

- "`huge-log` 的 3.3 GB 已包含在 `ai-cli-sessions` 里，清单保留展示但**不重复计入**总数。"（对应 `subsumed: true` 的 finding，标在它自己那张表里）
- 总数后面加一句"已剔除 N 条重叠（约 Y GB）"，让用户知道为什么加起来比表里每项之和少。

### 四、清完之后还剩多少

数据来自 `projection`，**一行一句话，紧跟在可删清单后面**。这是用户最想知道的那句"那我到底还剩多少"：

> 按 ✅ 档清完，C: 从剩 17.2 GB 变成 **43.7 GB**（可用率 10.2% → 26.5%），越过 20% 这条舒服线。⚠️ 档也全部确认的话，最多能到 70.1 GB（42.5%）。

规则：

- 用 `projection.drives[]` 里**对应盘符那一行**的 `afterSafeMB` / `afterSafePct`，不要拿全盘 `projectedFreeMB` 当某个盘的剩余（多盘机器上那个数是合计）。
- `afterAllMB` 只能当**上界**表述（"最多能到"），因为 caution 项要逐项拍板，不一定全删。
- `crossesPct` 非空时点出来（"越过 20% 这条线"），这是清理有没有意义的直观判据；`freePct` 清完仍 `< 5%` 时，`projection.warnings` 里会有对应条目，**必须转述**，不能只报喜。
- 必须带上"这是估算"的口径：`projection.note` 已写明两件事 —— 体积按目录项算，硬链接文件另有一个名字时并不会真的释放；而且 `clean.ps1` 默认删到**回收站**，要清空回收站空间才回来。用户问"我清了怎么没变"时就是这两条。

反例（不许写）：把 `safeMB` 直接加到"我的电脑"显示的可用空间上当既成事实，或说"清理后可释放 27.6 GB"却不给清理后的剩余值。

### 五、⛔ 别删清单

用 `neverTouch` 数组生成，说明为什么不能动。至少包含：

- `WinSxS` —— 与 System32 硬链接共享文件，**显示体积远大于真实占用**，手工删会损坏系统，只能用 DISM
- `System32` / `Fonts` / `assembly`
- `Program Files` 下已安装程序
- 用户文档、图片、桌面

并提醒：不要用任何第三方"一键清理大师"扫 C 盘。

## 结尾固定动作

- 给出总计：**可安全释放约 XX GB**（取 `totals.safeMB` / `totals.reclaimableMB`，**不要**自己把 `findings[].mb` 加一遍）。
- 紧接着给对应的一句剩余：**清完剩约 XX GB（XX%）**，取 `projection.drives[]` 里该盘那行。"能释放多少"和"还剩多少"必须成对出现，只给前者用户没法判断要不要动手。
- 说明本次**未删除任何文件**，等待用户指定要清理的项。
- 若某项要求先退出应用（Chrome、微信、飞书等），**单独高亮提醒**。
- 若存在 `anomalies`，放在报告靠前位置单独提示，格式：

> ⚠️ 异常发现：`<路径>` 占 **13.3 GB**，远超同类缓存正常量级（原因）

## anomalies 的 reasonCode 对照

脚本只输出机器码，中文由报告层翻译，不要指望脚本里带中文：

| reasonCode | 中文表述 |
|---|---|
| `cache-dir-exceeds-threshold` | 缓存类目录超过阈值 N MB，且规则判定为可清理 —— 典型的「隐形大户」 |
| `dir-exceeds-threshold` | 单目录超过阈值 N MB，需人工确认用途 |

`thresholdMB` 字段给出当时生效的阈值，直接用这个数字做对比说明。

---

## 文风要求

- 简体中文，结论先行，表格优先。
- 体积统一用 GB/MB，保留一位小数。
- 不写"建议您"这类客套话；直接给数字和动作。
- 不要堆砌形容词，篇幅控制在能一眼看完一屏的密度。
