# 对话内报告模板

在对话中直接输出，**默认不生成文件**。除非用户明确说"生成 HTML / 存成文件"。

---

## 标准结构

### 一、C 盘现状

首行给一句结论，例如：

> **C: 165 GB 总 / 已用 143 GB / 剩余 23 GB（87%）**

然后一张顶层目录表：

| 顶层目录 | 占用 | 说明 |
|---|---|---|
| `C:\Users` | **104 GB** | 主要消耗在这里 |
| `C:\Windows` | 30.9 GB | WinSxS 12.3 GB + System32 11.7 GB，系统本体不可动 |
| … | | |

用户目录量级大时，追加一张二级表（`AppData\Local` / `AppData\Roaming` / 各点目录）。

### 二、为什么"掉得特别快"

这是本 skill 相对普通空间分析工具的核心价值。数据来自 `growth` 数组。

| 增长源 | 当前体积 | 增长特征 |
|---|---|---|
| Chrome Service Worker 缓存 | 13.3 GB | 按月累积：8月 1.9G → 9月 2.5G → 10月 3.7G，从不回收 |

- 首次运行（`previousAt` 为 `null`）时，明确说明"本次无历史可比，先建立基线"，不要编造增长率。
- 若 `growth` 为空但存在 `recentBig`，改用"最近 N 天内新增的大文件"作为增长证据，并注明这是按文件修改时间反推的。

### 三、可删清单

按 `risk` 分档，每档一张表。**必须逐项给出释放量**。

**✅ 可直接清理（约 XX GB）**

| 目标 | 释放 | 操作 |
|---|---|---|
| Chrome `Service Worker`（先完全退出 Chrome） | 13.3 GB | 删除该目录 |
| `AppData\Local\npm-cache` | 8.5 GB | `npm cache clean --force` |

**⚠️ 需你确认（约 XX GB）**

| 目标 | 释放 | 顾虑 |
|---|---|---|
| `.codex\sessions` | 2.3 GB | AI 对话历史，删了不可恢复 |
| … | | 用 finding 的 `cleanHint` / `why` 填这一列 |

### 四、⛔ 别删清单

用 `neverTouch` 数组生成，说明为什么不能动。至少包含：

- `WinSxS` —— 与 System32 硬链接共享文件，**显示体积远大于真实占用**，手工删会损坏系统，只能用 DISM
- `System32` / `Fonts` / `assembly`
- `Program Files` 下已安装程序
- 用户文档、图片、桌面

并提醒：不要用任何第三方"一键清理大师"扫 C 盘。

---

## 结尾固定动作

- 给出总计：**可安全释放约 XX GB**。
- 说明本次**未删除任何文件**，等待用户指定要清理的项。
- 若某项要求先退出应用（Chrome、微信、飞书等），**单独高亮提醒**。
- 若存在 `anomalies`，放在报告靠前位置单独提示，格式：

> ⚠️ 异常发现：`<路径>` 占 **13.3 GB**，远超同类缓存正常量级（原因）

---

## anomalies 的 reasonCode 对照

脚本只输出机器码，中文由报告层翻译，不要指望脚本里带中文：

| reasonCode | 中文表述 |
|---|---|
| `cache-dir-exceeds-threshold` | 缓存类目录超过阈值 N MB，且规则判定为可清理 —— 典型的「隐形大户」 |
| `dir-exceeds-threshold` | 单目录超过阈值 N MB，需人工确认用途 |

`thresholdMB` 字段给出当时生效的阈值，直接用这个数字做对比说明。

---

## 文风要求

- 简体中文，结论先行，表格优先。
- 体积统一用 GB/MB，保留一位小数。
- 不写"建议您"这类客套话；直接给数字和动作。
- 不要堆砌形容词，篇幅控制在能一眼看完一屏的密度。
